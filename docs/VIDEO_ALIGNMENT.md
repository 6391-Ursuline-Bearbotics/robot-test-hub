# Manual video alignment core

The `robot_test_hub.video_alignment` module implements the manual mathematics/evidence portion of T17. It starts no recorder, camera, robot connection or native process, and changes no media or robot logs. The local service and [manual investigation browser](VIDEO_INVESTIGATION.md) wrap this core for revisioned calibration and explicit robot-interval frame selection. [Saved-context association](VIDEO_CONTEXT.md) now supplies candidate intervals from saved notes and runs. Media preview, clip preservation and export remain incomplete.

## Evidence and use

`VideoSegment.from_manifest(recording_folder, manifest)` consumes a T16 recorder `closed_verified` manifest. It checks camera/session/capture identity, immutable file size/SHA256, exact frame `pts_ns` and optional `duration_ns`, ordering, final frame bounds and path confinement. Frame metadata and its canonical manifest SHA256 are snapshotted. Unknown frame durations do not provide coverage. Files are reverified when selecting footage; loss produces a gap and changed bytes produce an integrity error.

Create `ManualAnchor(robot_ns, segment_id, source_sha256, frame_index, robot_uncertainty_ns, video_uncertainty_ns, evidence_label)` for an operator-observed cue. The video time comes from the actual indexed frame, never from nominal FPS or recorder launch UTC. Uncertainty must include the relevant cue actuation, camera exposure, sampling and operator identification limits; zero is a mathematical fixture/explicit operator assumption, not a measured accuracy guarantee.

Each `CalibrationWindow(continuity_id, start_robot_ns, end_robot_ns, anchors, segment_ids, ...)` explicitly identifies the recording segments in one uninterrupted PTS domain. Multiple anchors fit a centered affine clock using exact rational arithmetic and publish drift in ppm and per-anchor residuals. Validity cannot extend beyond the anchor hull. Overlapping recording PTS, camera restart, different capture/session/camera identities and different robot boots cannot silently share a calibration. Represent an in-capture PTS reset with separate windows and segment lists; robot intervals between windows remain unmapped. Discontinuity detection is manual at this stage.

A single anchor is accepted only with explicit decimal-string `assumed_scale`, `assumed_drift_uncertainty_ppm` and a specified validity interval containing that anchor. Its drift remains assumed and uncertainty grows with distance from the anchor. This provides a limited manual fallback without claiming observed drift.

`ManualAlignment(robot_id, boot_id, camera_id, session_id, capture_id, segments, windows)` creates the immutable mapping snapshot. `map_interval(robot_id, boot_id, start_robot_ns, end_robot_ns, event_id=..., run_id=...)` maps a selected event or run and returns actual frame indexes/PTS/durations plus source and manifest hashes. Nanoseconds accept integers or canonical decimal strings, reject floats, and return strings. A point event selects its containing frame; frame exposures use half-open intervals. Uncertainty bounds round outward to integer ns. No raw log or source video is rewritten.

Results distinguish `mapped`, `partial`, `gap`, `outside` calibrated windows and `unavailable` for another clock domain. Missing footage, dropped-frame coverage, unknown durations and uncalibrated robot intervals are explicit. `mapped` means the requested uncertainty envelope is covered by the referenced frame spans, not that physical synchronization is measured accurate.

The bound propagates anchor uncertainty through affine-fit weights, uses a conservative possible clock scale for robot-side anchor error, and includes the largest residual plus explicit `model_uncertainty_ns`. Bounds are conditional on the declared affine continuity model and supplied uncertainty; they cannot infer unobserved nonlinear clock behavior or exposure delay. High residuals remain visible and widen selection. Every document/result retains `manual_unqualified` and `measured_camera_alignment: false`, even for small mathematical residuals.

## Revisions

`AlignmentRevisions(folder, alignment_id).append(revision, mapping, expected_previous_sha256=...)` writes immutable JSON files with a hash-linked predecessor. The first revision has no parent; later revisions require its exact digest and preserve the clock domain and existing source evidence. Identical retries return the same revision; changed retries fail. Publication uses a flushed temporary file and an atomic hard-link create so an existing revision cannot be overwritten. Writers must be externally serialized; unsupported filesystems fail rather than downgrade publication.

`load(revision, segments, expected_sha256=...)` verifies the pinned revision/parent and reconstructs its fit from the manual anchors. Parent identity, robot/boot/camera/session/capture domains and shared original evidence are validated during both append and load. A recording path cannot be reassigned to another segment identity, either within a mapping or across revisions. Recomputed fit and provided recording evidence must match the saved document. Changed revisions retain old files and return distinct mapping fingerprints. Existing interrupted `.writing` evidence is preserved if an exclusive temporary-file create fails; inspect it before retrying. Decimal assumption exponents/magnitudes are bounded before exact-rational allocation. The service now serializes publication under its shutdown ownership guard and exposes pinned revision selection and a two-cue browser form; the file contract remains independently usable.

## Verification and remaining gaps

Pinned `.venv` command: `.venv\Scripts\python.exe -m unittest discover -s tests -p test_video_alignment.py -v`. Twenty deterministic protocol tests cover independently known variable frame PTS/gaps, drift and residuals, nanoseconds above JavaScript integer precision, outward rounding and point-expansion overflow, anchor/model uncertainty, explicit single-anchor assumptions, bounded decimal exponents, calibrated bounds, PTS resets, camera/capture/boot isolation, revision retry/conflicts/reload/parent-domain checks, preservation of interrupted temporary evidence, source-path identity conflicts, missing footage, changed hashes and path/symlink rejection. Synthetic fixture bytes are not encoded video. The host may skip the symlink case when Windows privileges prohibit creation.

The separate opt-in `test_video_alignment_native.py` now passes with actual encoded lavfi footage and pinned FFmpeg/FFprobe 9.0.2. A generated 10 Hz profile drops source frames 2 and 6 per second and displays white cues at source frames 1, 5 and 9. Independently decoded pixels identify those cue frames; FFprobe supplies actual PTS. A deliberately different synthetic robot clock yields an exact 100/99 affine fit. The test verifies actual frame selection, uncertainty and dropped-frame gaps, immutable revision reload and new capture isolation after restarting the encoder. It leaves original bytes unchanged and reaps both encoders. These are generated-video and mathematical-clock results, not physical synchronization measurements. Executable hashes and local invocation are recorded in [RECORDING](RECORDING.md).

Still required for T17/V16 completion: cue detection in live footage; measured camera/LED timing and nonlinear drift/discontinuity behavior; UI preview and preservation/export integration; documented and verified AdvantageScope manual alignment workflow. The explicit robot-interval action retains a note as context; the separate saved-context action propagates its time estimate through imported clock anchors. Neither establishes physical wall-clock synchronization. Less than 100 ms remains an unachieved commissioning target. No physical camera, hardware or robot was operated.
